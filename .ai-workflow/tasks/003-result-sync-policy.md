# Task 003 — 결과 보고서 동기화 의무화

## 목적
`/run-task`로 실행한 작업은 결과 보고서까지 GitHub에 반영되어야 완료로 취급되도록 스킬 규칙을 강화합니다.

## 수정 범위
- `.claude/skills/run-task/SKILL.md`
- `.ai-workflow/results/003-result-sync-policy.md` (결과 보고서)
- 다른 파일 변경 금지

## 요구사항
1. 모든 `/run-task` 작업은 `.ai-workflow/results/<작업 ID>.md`를 반드시 작성합니다. 구현이 실패하거나 중단된 경우에도 가능한 범위에서 실패·중단 이유를 기록합니다. 단, 작업 트리가 이미 더럽거나 저장소 확인에 실패해 안전상 파일을 작성하면 안 되는 경우에는 파일을 생성하지 않고 사용자에게 보고합니다.
2. 결과 보고서에 작업 ID, 상태(완료/부분 완료/실패/중단/동기화 대기), 구현 내용, 수정 파일, 테스트 결과, 보안 검사 결과, 미해결 문제를 기록합니다. 민감정보 원문 금지.
3. 커밋·Push 승인을 요청할 때는 결과 보고서를 **반드시 커밋 예정 파일 목록에 포함**합니다. 사용자가 결과 보고서 제외를 요구하면 완료로 처리하지 않고 재확인합니다.
4. 승인 후 관련 코드 파일과 결과 보고서를 함께 스테이징하고, 기존 2단계 검사를 통과한 뒤 커밋·Push합니다.
5. Push 실패 시 완료를 선언하지 않고 '동기화 대기'라고 보고합니다. 인증 오류, 네트워크 오류, 충돌을 임의로 우회하거나 강제 Push하지 않습니다. 로컬 보고서의 상태를 변경해야 한다면 재승인을 요청합니다.
6. Push 성공 후 `git status` 및 `git ls-remote origin refs/heads/main` 또는 이에 준하는 읽기 전용 검증으로 원격 반영을 확인합니다. 검증에 실패하면 성공을 단정하지 않고 사용자에게 알립니다.
7. 기존 승인 절차, 개인정보·중요문서 보호, 외부 전송 제한, 프로젝트 접근 범위, 금지 명령을 그대로 유지합니다.
8. `/run-task`가 ChatGPT에 자동으로 메시지를 보내거나 ChatGPT를 호출한다고 설명하지 않습니다. 사용자가 ChatGPT에 '작업 완료, 확인해 줘'라고 말하면 ChatGPT가 GitHub를 조회하는 방식임을 명시합니다.

## 검증 및 결과
- YAML frontmatter 유효성 확인
- 필수 보고서 경로·커밋 포함·Push 실패 처리 규칙 확인
- `.ai-workflow/results/003-result-sync-policy.md`에 구현·검증 내용을 기록
- 커밋·Push는 반드시 사용자 승인 후 진행
